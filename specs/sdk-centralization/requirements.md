# CONN-ANSIBLE-TOWER-MCP-SDK-CENTRALIZATION — Requirements

Governing specification: [spec.md](spec.md).

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-ANSIBLE-TOWER-MCP-SDK-CENTRALIZATION-R001` | **Governed HTTP.** The connector must reach Ansible Tower only through the SDK governed HTTP client in `ansible_tower_mcp/api/api_client_base.py`. It must not import `requests`. Caller chain: any Tower tool (`ansible_tower_mcp/mcp/tools.py`) -> `get_client` (`ansible_tower_mcp/auth.py`) -> `BaseApiClient` (`ansible_tower_mcp/api/api_client_base.py` line 21) -> `create_http_client` (line 41) from `scion_sdk.http.client`. Shape: `BaseApiClient.__init__` builds its session with `create_http_client(HttpClientOptions(...))` and no `requests` import; `tests/test_sdk_centralization.py::test_api_client_uses_sdk_http_client` checks the client type and the source. | `tests/test_sdk_centralization.py::test_api_client_uses_sdk_http_client` must observe an SDK client and no `requests` import. |
| `CONN-ANSIBLE-TOWER-MCP-SDK-CENTRALIZATION-R002` | **Shared pagination.** `handle_pagination` in `ansible_tower_mcp/api/api_client_base.py` must walk list pages with the SDK `PaginationIterator` in `next_url` mode (SDK `SCION-CENTRALIZED-CAPABILITIES-R004`). It reads the body `next` link and records from `results`. The connector must ship no page loop of its own. A `next` link that changes the scheme, host, or port must raise `PaginationOriginError` before the client requests it. A repeated `next` link must end the sweep. Caller chain: list tools such as `ansible_tower_jobs` -> `api_client_jobs.py::list_jobs` -> `BaseApiClient.handle_pagination` (`ansible_tower_mcp/api/api_client_base.py` line 202) -> `scion_sdk.httpsupport.pagination.PaginationIterator`. Shape: `handle_pagination` wraps `self.request` in a `fetch` callback and builds `PaginationIterator(mode="next_url", items_path="results", max_items, max_pages)`; the SDK raises `PaginationOriginError` and stops on a repeated link; tests are in `tests/test_sdk_centralization.py`. | `tests/test_sdk_centralization.py::test_pagination_rejects_cross_origin_cursor`, `test_pagination_follows_relative_and_absolute_next`, `test_pagination_rejects_origin_change`, and `test_pagination_stops_on_a_repeated_next` pass. |
| `CONN-ANSIBLE-TOWER-MCP-SDK-CENTRALIZATION-R003` | **Adopt scion-sdk 0.10.0 import paths.** ansible-tower-mcp must import only paths that exist in `scion-sdk` 0.10.0 and must raise its floor to that release. The release removes the pre-layer paths without an alias (`SCION-CENTRALIZED-CAPABILITIES-R046`). Stage: dependency and import adoption. Edits, by file: `ansible_tower_mcp/api/api_client_base.py`: `create_http_client` to `build_http_client(options)`; `tests/test_ansible_tower_coverage.py`: `create_http_client` to `build_http_client(options)`; `tests/test_ansible_tower_mcp_brute_force_coverage.py`: `create_http_client` to `build_http_client(options)`; `tests/test_coverage_edge_cases.py`: `create_http_client` to `build_http_client(options)`. Raise the `pyproject.toml` requirement `scion-sdk[mcp]>=0.7.0,<0.8.0` to `scion-sdk>=0.10.0,<0.11.0` with the same extras and regenerate `uv.lock`. A client built by the old factory keeps its options argument; `build_http_client(options, async_=True)` returns the async client. No wrapper, alias or fallback import stays. Caller chain: the connector entry point `ansible_tower_mcp` -> its modules above -> the public `scion_sdk` modules. Shape: import edits in the files named, one `pyproject.toml` edit and one lock edit; the new test reuses `ast` from the standard library. Depends on: SCION-CENTRALIZED-CAPABILITIES-R046. | Test: `tests/test_scion_sdk_0_10_imports.py::test_every_scion_sdk_import_resolves_on_the_pinned_release` (L2) parses every Python file of `ansible_tower_mcp` and `tests` and asserts each imported `scion_sdk` module resolves with `importlib.util.find_spec`. |
